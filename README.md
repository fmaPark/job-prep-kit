# job-prep-kit

취업 준비를 **파일로 운영**하기 위한 폴더 구조와 대시보드입니다.

회사별 폴더에 자소서를 쓰다 보면 같은 경험이 폴더마다 조금씩 다른 문장으로 복제되고, 내 최신 이력이 어디 있는지 모르게 됩니다.
그래서 경험·역량 같은 사실은 `me/` 한 곳에만 두고, 회사별 자소서·면접 준비는 그 사실을 조합해서 만듭니다.
개발, 디자인, 마케팅, 영업, 사무 어느 직군이든 쓸 수 있고, AI(Claude, ChatGPT 등)와 함께 쓰는 것을 전제로 설계했습니다.

## 무엇을 해주나

- **사실은 한 곳에** — 경험을 사건 단위로 쪼개 `me/experiences/`에 저장하고, 모든 자소서는 여기서만 재료를 가져옵니다.
- **지원할지부터 판단** — 공고를 하드 필터와 100점 판단표(`me/target-criteria.md`)로 채점합니다. 인상이 아니라 근거로 정하고, 지원하지 않을 공고는 폴더도 만들지 않습니다.
- **회사별 준비 폴더** — 템플릿을 복사하면 공고 · 리서치 · 전략 · 자소서 · 지원서 칸 · 면접 · 필기·과제 문서가 한 벌 생깁니다. 경력기술서나 면접 복기 같은 선택 문서는 `optional/`에 있습니다.
- **공고 ↔ 경험 매핑표** — 자소서보다 먼저 채웁니다. 비어 있는 칸이 곧 면접 압박 질문입니다.
- **대시보드** — 진행 중인 지원, 다음 일정 D-day, 서류 → 필기·과제 → 면접 결과 깔때기, 경험이 몇 군데에 쓰였는지를 한 화면에 보여줍니다. `applications/index.md`의 지원 보드도 함께 갱신합니다.
- **회사를 가로지르는 기록** — 실제로 받은 면접 질문, 필기·과제에서 틀린 유형, 지원 회고를 `library/`에 쌓습니다. 지원 건수가 늘수록 여기가 두꺼워져야 합니다.
- **AI 작업 규칙** — `CLAUDE.md` 한 장으로 AI에게 규칙을 줍니다. 사실은 `me/`에서만 가져오고, 초안 작성과 반박을 맡습니다. 자소서 · 포트폴리오 작성 규칙은 `library/`에 따로 있습니다.

## 필요한 것

| 항목 | 필요한 때 | 설명 |
|---|---|---|
| **[Obsidian](https://obsidian.md)** | 링크 · 대시보드 | 문서를 읽고 쓰는 것만이면 어떤 편집기든 됩니다. 문서 안의 링크와 대시보드의 "문서 열기"를 쓰려면 필요합니다. 아래 안내 참고 |
| **Python 3.8 이상** | 대시보드 | 대시보드를 만들 때만 필요합니다. 따로 설치할 라이브러리는 없습니다 |
| Git | 선택 | ZIP 다운로드로 대신할 수 있습니다 |

> **Obsidian 안내.** 문서 안의 `[[링크]]`와 대시보드의 "문서 열기" 링크는 **기본적으로 Obsidian에서 열리도록** 되어 있습니다.
> 마크다운 파일 자체는 어떤 편집기로도 읽고 쓸 수 있지만, 링크가 동작하려면 이 폴더를 Obsidian **보관함(vault)** 으로 한 번 열어 두어야 합니다.
> Obsidian을 쓰지 않는다면 대시보드를 만들 때 `--links vscode` 또는 `--links file` 옵션을 붙이세요. 자세한 내용은 [대시보드 문서](docs/dashboard.md)에 있습니다.

## 시작하기

> 자기 자료로 쓸 저장소는 **비공개(private)** 로 두세요. 이력서 · 자소서 · 회사별 전략이 들어갑니다.
> **이 저장소를 Fork하지 마세요.** 공개 저장소의 fork는 비공개로 바꿀 수 없습니다. `Use this template`으로 Private 저장소를 만들거나 ZIP으로 받으세요([방법](docs/getting-started.md#비공개-저장소로-올리기-선택)).
> 이력서 · 포트폴리오 원본은 `me/assets/`에 둡니다. git에 올라가지 않으니 따로 백업하세요.

1. **내려받기** — 이 페이지 위쪽의 `Code → Download ZIP`을 눌러 받고 압축을 풉니다. 터미널이 낯설거나 Windows라면 이 방법이 가장 덜 막힙니다. 터미널이 익숙하면 대신:
   ```bash
   git clone https://github.com/fmaPark/job-prep-kit.git 취업준비
   cd 취업준비
   rm -rf .git && git init      # 여기서부터는 내 기록 (Windows PowerShell: Remove-Item -Recurse -Force .git)
   ```
2. **Obsidian에서 열기** — Obsidian을 실행하고 "보관함으로 폴더 열기(Open folder as vault)"에서 압축 푼 폴더를 고릅니다.
3. **처음 30분: `me/` 채우기** — `me/profile.md`(기본 정보와 「지원서 기재 표준」) → `me/experiences/`에 경험 2~3개(경험 하나 = 파일 하나) → `me/target-criteria.md`의 하드 필터 3개. `skills.md` · `narrative.md` · `portfolio.md`는 경험이 쌓인 뒤에 채웁니다.
4. **첫 지원 건** — 아래 흐름대로 공고부터 판단하고, 지원하기로 하면 `applications/_template/` 폴더를 복사해 `applications/2026-09-회사명-직무/`로 이름을 바꾼 뒤 `meta.md`부터 채웁니다.

단계별 자세한 설명은 [시작 가이드](docs/getting-started.md)에 있습니다.

## 지원 건 하나의 흐름

| 단계 | 남기는 곳 |
|---|---|
| 1. 공고 → 스크리닝 (지원할지 판단) | 채팅으로 판정. 기준은 `me/target-criteria.md`, 절차는 `playbook.md` 2.5 |
| 2. 폴더 생성 · 공고 원문 | `applications/_template/` 복사 → `meta.md`, `jd.md` |
| 3. 전략 매핑 (자소서보다 먼저) | `strategy.md` |
| 4. 지원서 칸 · 자소서 | `application-form.md`, `cover-letter.md` (+ `drafts/`) |
| 5. 제출 전 통독 · 제출 | `application-form.md` 「제출 확정값」, `meta.md` |
| 6. 필기·과제 · 면접 | `assessment.md`, `interview.md`, `library/question-bank.md` |
| 7. 결과 · 회고 → `me/` 반영 | `meta.md`, `library/retrospectives/`, `me/` |

상태가 바뀔 때마다 그 회사 폴더의 `meta.md`를 고칩니다. 제출 뒤에는 다음 전형 일정, 끝나면 어느 전형에서 끝났는지를 적고, 칸 설명은 파일 안 메모에 있습니다.
단계별 절차와 AI에게 던질 요청 문장은 [플레이북](playbook.md)에 있습니다.

## 대시보드 만들기

이 폴더에서 터미널을 열고 아래를 실행합니다. (Windows는 `python3` 대신 `py` 또는 `python`)

```bash
python3 build-dashboard.py
```

`dashboard.html`이 만들어지면 브라우저로 엽니다. `applications/index.md`의 파이프라인 · 일정 · 결과 표도 함께 갱신됩니다. 문서를 고친 뒤에는 다시 실행해야 반영됩니다.
실행 옵션, 읽어 가는 파일, 링크가 안 열릴 때의 해결법은 [대시보드 문서](docs/dashboard.md)를 보세요.

문서 규격 점검은 `python3 check-repo.py`입니다. 프론트매터 `type`이 빠진 문서를 알려 주기만 하고 아무것도 고치지 않습니다.

## AI와 함께 쓰기

`CLAUDE.md`가 AI에게 주는 작업 규칙입니다. Claude Code는 이 파일을 자동으로 읽고,
웹 챗에서는 내용을 프로젝트 지침(custom instructions)에 붙여 넣으면 됩니다. 다른 도구는 그 도구의 규칙 파일로 옮겨 씁니다.
자소서 · 포트폴리오 작업 때 AI는 `library/cover-letter-rules.md` · `library/portfolio-rules.md`도 읽습니다. 두 문서 끝 「내 규칙」에 자기 규칙을 덧붙여 키웁니다.

처음에는 이 순서로 요청해 보세요.

1. "`/me/experiences/_template.md` 형식으로 내 경험 하나를 인터뷰해서 원자 파일로 만들어줘. 내가 말하지 않은 사실은 `[[확인필요: …]]`로 남겨줘."
2. "이 공고 원문으로 지원 여부를 판단해줘. playbook 2.5 절차대로 하드 필터, 근거 매핑표, 판단표까지 채워서."
3. "`/me/experiences/`를 읽고, 이 공고와 매핑되는 경험을 찾아서 `strategy.md`의 매핑표를 채워줘."

나머지 요청 문장과 도구별 적용법은 [AI와 함께 쓰기](docs/ai-guide.md)에 있습니다.

## 한계

- **대시보드는 스냅샷입니다.** 문서를 고쳐도 스스로 바뀌지 않습니다. 볼 때마다 다시 만들어야 합니다.
- **링크는 Obsidian을 가정합니다.** 다른 편집기에서는 대시보드를 `--links` 옵션으로 다시 만들어야 하고, 문서 안의 `[[링크]]`는 그대로 동작하지 않습니다.
- **경험이 쓰인 횟수는 파일 이름 등장 기준입니다.** 매핑표나 자소서에 경험 파일 링크를 걸지 않으면 0으로 셉니다.
- **지원서를 대신 내주지 않습니다.** AI 규칙도 초안과 반박까지입니다. 제출과 최종 판단은 사람이 합니다.
